# Abate: Next.js 16.4.2 cheat sheet for coding agents

Next.js 16.4.2 App Router, React 19.3, TypeScript, Tailwind v4, `src/` layout (`@/` = `src/`), Supabase with the secret key (server only), Claude API, Vercel. Keep `cacheComponents: true` and `partialPrefetching: true`. Nothing in the docs conflicts with our pages, and `partialPrefetching` requires `cacheComponents`. Doc paths are relative to `node_modules/next/dist/docs/01-app/`. Open the doc before guessing.

## Top 10 things that differ from what you remember

1. **Route-level opt-outs are gone.** Exporting `dynamic`, `revalidate` or `fetchCache` is an error. `dynamicParams` fails the build. `runtime` is unsupported, even `'nodejs'`. `unstable_noStore()` is unnecessary. There is no force-dynamic, because uncached reads already run on every request. (02-guides/migrating-to-cache-components.md; 03-api-reference/03-file-conventions/02-route-segment-config/index.md, runtime.md)
2. **Request data outside `<Suspense>` fails the build.** It no longer quietly makes the route dynamic. This applies to awaiting `params`, `searchParams`, `cookies()`, `headers()` or a Supabase query (`blocking-prerender-dynamic` / `-runtime`). The only other way out is `export const instant = false` on the segment, which allows a blocking route. (02-guides/building.md "Prerender validation"; 01-getting-started/08-caching.md)
3. **`new Date()`, `Date.now()`, `Math.random()` and `crypto.randomUUID()` in a prerendered render path fail the build.** `instant = false` does not clear this error. They are fine after an awaited uncached query inside `<Suspense>`, in a Server Action, and in event handlers or effects. Client Components prerender during SSR too, so guard a render-time read there with `use(io())` inside `<Suspense>`, or read the clock in `useEffect`. (03-api-reference/04-functions/io.md; 02-guides/migrating-to-cache-components.md "Adopting incrementally")
4. **`params` and `searchParams` are only Promises.** Sync access was removed in 16. Ignore page.md's leftover line that says sync access "still works in 15". `PageProps<'/case/[token]'>`, `LayoutProps` and `RouteContext` are global types generated by `next dev|build|typegen`. Never import them. (02-guides/upgrading/version-16.md "Async Request APIs"; 03-api-reference/03-file-conventions/page.md)
5. **A mutation re-renders the page only if you ask.** `refresh()` is new, comes from `next/cache` and works only in Server Actions. It re-renders the current route inside the action response. An action that calls none of `refresh`, `revalidatePath`, `updateTag`, `redirect` or a cookie set returns only its value. `revalidateTag(tag, profile)` now needs the second argument; the one-argument form is a TS error. (02-guides/server-actions.md; 03-api-reference/04-functions/refresh.md; 02-guides/upgrading/version-16.md)
6. **Server Action bodies are capped at 1MB**, and the cap counts multipart overhead. Raise it with `experimental.serverActions.bodySizeLimit`. It still sits under `experimental`, and the `NextConfig` types confirm that. A client sends actions one at a time, so `Promise.all` over several actions runs them back to back. (03-api-reference/05-config/01-next-config-js/serverActions.md; 02-guides/server-actions.md)
7. **`generateStaticParams` returning `[]` is a build error** (`empty-generate-static-params`). Leave it out of `/case/[token]` entirely. (02-guides/migrating-to-cache-components.md)
8. **Routes are hidden with React `<Activity>`, not unmounted.** Up to 3 stay mounted. Inputs, `useState` and `useActionState` results survive Back, and effects re-run every time a route is shown again. (03-api-reference/05-config/01-next-config-js/cacheComponents.md; 02-guides/preserving-ui-state.md)
9. **Tooling moved.** Turbopack is the default for dev and build, and a `webpack()` config fails the build. `next lint` is gone and `next build` no longer lints. `middleware.ts` is deprecated and renamed to `proxy.ts`, which exports `proxy`, runs on Node only and lives in `src/proxy.ts` in our layout. (02-guides/upgrading/version-16.md; 03-api-reference/03-file-conventions/proxy.md)
10. **Hooks and props changed.** `error.tsx` receives `{ error: unknown; retry }`. `retry` (stable in 16.3) re-fetches; `reset` does not. `useFormState` is deprecated in favor of `useActionState` from `react`. With `partialPrefetching`, a default `<Link>` prefetches only the route's App Shell. (03-api-reference/03-file-conventions/error.md; 02-guides/upgrading/version-15.md; 03-api-reference/05-config/01-next-config-js/partialPrefetching.md)

## Contradictions resolved

| Topic | Where the notes disagreed | Decision |
| --- | --- | --- |
| Case page shape | Suspense child, or async page + `loading.tsx`, or `instant = false` | **Use a Suspense child.** The route shows ◐ and the header stays in the shell. `loading.tsx` also works, but the whole page then falls back to one skeleton. Use `instant = false` only if a real 404 status becomes a requirement. |
| "Days unresolved" | Needs `await connection()`, or is fine after the query | **Fine after the awaited Supabase query inside the Suspense child** (io.md, "When you don't need io()"). Compute it with `nyDate()` from `@/lib/domain/dates`, not `new Date()` math, because Vercel runs in UTC. A component with no earlier await should use `await io()`. Prefer `io()` over `connection()`, which also blocks prefetch. |
| Body limit | `'2mb'`, `'3mb'` or `'4mb'`; the working tree now has `'6mb'` | **Use `'4mb'`** and cap one submit at about 10 photos of ~300KB (about 6 at 600KB). Vercel rejects function request bodies over 4.5MB before Next sees them (a Vercel limit, not in the Next docs), so `'6mb'` gains nothing there. |
| After a mutation | `refresh()` or `revalidatePath` | **Use `refresh()`.** Called from an action, `revalidatePath` also refreshes every previously visited page when the user goes back to it (revalidatePath.md). |
| Passing the token | `.bind` or a hidden input | **Use `.bind(null, token)`.** It works with or without `useActionState` and supports progressive enhancement (forms.md). |
| Action return values | `<form action={markFixed}>` where the action returns `{ ok }` | **A plain `<form action>` function must return `void`.** Returning an object is a TS2322 error (checked with `tsc` against this repo). To return values, use `useActionState`. |
| `<Link>` to a case | `prefetch={true}` or the default | **Use the default.** Case data is uncached, so `prefetch={true}` adds nothing and costs a server call per link. |
| Funnel events | `after()` in actions, or a guarded client effect | **Use `after()` inside actions** for the created, sent, fixed and help events. For view events (estimate viewed, letter opened), use a first-mount ref guard or a click handler. Don't log them during the server render, including via `after()` in `CaseView`: `refresh()` re-renders the case view and would count them twice (our inference). |
| Tailwind loader | The scaffold's `@tailwindcss/turbopack` rule, vs docs saying stylesheet loaders are "not currently supported" | **Keep the rule.** `next build` on 2026-10-18 emitted Tailwind utilities with it. If it breaks, switch to the documented `@tailwindcss/postcss` + `postcss.config.mjs`. |
| `server-only` in Vitest | Keep it out of tested modules, or not | **Already handled.** `vitest.config.mts` aliases `server-only` to `src/test/empty-module.ts`. |

## Rendering & caching (cacheComponents)

- **Landing page:** static JSX is prerendered automatically (○). To lock it as static, add `export const ensureStatic = 'navigation'` to `src/app/page.tsx` only. It also covers the root layout for `/`. Never put it in the root layout, because there it would apply to `/case/[token]` too. (01-getting-started/08-caching.md; 03-api-reference/03-file-conventions/02-route-segment-config/ensureStatic.md)
- **Never put `'use cache'` on case data**, whether on a function, a component or a whole file in `lib/`. Cached entries are reused across requests with the same arguments, so a tenant would see stale data after a mutation. Fresh private data goes behind `<Suspense>`. (01-getting-started/08-caching.md "Streaming uncached data"; 03-api-reference/01-directives/use-cache.md)
- **If you do use `'use cache'`, use it for public data only.** The function must be async, with serializable arguments and return values. Call `cacheLife()` inside the scope, never at module scope. Never touch `cookies()`, `headers()`, `searchParams` or a request promise inside it: await outside and pass plain values in. (03-api-reference/01-directives/use-cache.md; 03-api-reference/04-functions/cacheLife.md)
- **Don't expect runtime savings on Vercel.** The default `'use cache'` store lives in memory per instance, and no entry carries over to a new deploy. (03-api-reference/01-directives/use-cache.md "Runtime caching considerations")
- **Timestamps and random values:** compute them after an awaited uncached query inside Suspense, or in a Server Action. Otherwise, call `await io()` (server) or `use(io())` (client) inside a `<Suspense>`, or capture the value once with `'use cache'`. (03-api-reference/04-functions/io.md; 01-getting-started/08-caching.md)
- **"Today" means New York's today.** Use `nyDate()` (an `Intl` formatter with `America/New_York`) for any date rendered on the server. `toISOString()` gives tomorrow's date after 8pm EDT. `toLocaleDateString()` on the server (UTC) can differ from the phone and cause a hydration mismatch.

```tsx
// Footer year (server component file): captured once, not per request
import { cacheLife } from 'next/cache'
async function Year() { 'use cache'; cacheLife('days'); return <>{new Date().getFullYear()}</> }
```

```tsx
// src/app/start/today-default.tsx. Parent: <Suspense fallback={<input type="date" name="started_on" />}>
'use client'
import { use } from 'react'
import { io } from 'next/cache'
import { nyDate } from '@/lib/domain/dates' // pure module, safe on the client
export function TodayDefault() {
  use(io())
  const today = nyDate() // same value on server and phone, so no hydration mismatch
  return <input type="date" name="started_on" max={today} defaultValue={today} />
}
// Alternative already used in start-form.tsx: useState('') + useEffect(() => setToday(...), []).
```

- **Client hooks:** wrap any component that calls `useSearchParams()` in `<Suspense>`. Do the same for `usePathname`, `useParams` and `useSelectedLayoutSegment(s)` in a layout above `/case/[token]`, and push the hook down to a leaf component. Without the boundary the build fails, and `'use client'` does not exempt the component. (02-guides/migrating-to-cache-components.md; 03-api-reference/04-functions/use-search-params.md)
- **Layouts:** keep uncached data out of `layout.tsx`. A `loading.tsx` does not cover the layout in its own segment. (03-api-reference/03-file-conventions/layout.md; 03-api-reference/03-file-conventions/loading.md)
- **Cookies and headers:** read them only inside a Suspense-wrapped component, and never in the root layout. Set them only in a Server Action or Route Handler. (03-api-reference/04-functions/cookies.md)
- **Verify:** in the `next build` route table, `/` should show ○ and `/case/[token]` should show ◐. Also open every route in `next dev` and read the overlay, because some insights (for example "URL data outside of Suspense") never fail the build. (02-guides/building.md; 02-guides/adopting-partial-prefetching.md)

## Data reads on dynamic pages

Keep the page component synchronous. Await `params` and the query only inside a child under `<Suspense>`. (02-guides/migrating-to-cache-components.md "Await params inside Suspense"; 01-getting-started/08-caching.md)

```tsx
// src/app/case/[token]/page.tsx  (no generateStaticParams, no dynamicParams, no 'use cache')
import type { Metadata } from 'next'
import { Suspense } from 'react'
import { notFound } from 'next/navigation'
import { getCaseBundle } from '@/lib/cases/repo'
import { daysBetween, nyDate } from '@/lib/domain/dates'

export const metadata: Metadata = { title: 'Your case', robots: { index: false, follow: false } }
export const maxDuration = 60 // also the timeout for every Server Action on this page (Claude call)

export default function Page({ params }: PageProps<'/case/[token]'>) {
  return (
    <main>
      <CaseHeader /> {/* URL-independent, so it ships in the static shell */}
      <Suspense fallback={<CaseSkeleton />}>
        <CaseView params={params} />
      </Suspense>
    </main>
  )
}

async function CaseView({ params }: Pick<PageProps<'/case/[token]'>, 'params'>) {
  const { token } = await params
  const c = await getCaseBundle(token) // uncached: runs on every request
  if (!c) notFound()
  const daysOpen = daysBetween(c.record.firstReportedOn, nyDate()) // OK: after the awaited query
  return <Timeline c={c} daysOpen={daysOpen} />
}
```

```ts
// src/lib/cases/repo.ts (exists): server-only, React.cache, no 'use cache'
import 'server-only'
import { cache } from 'react'
// React.cache dedupes within ONE request only, so it is safe for private data.
export const getCaseBundle = cache(async (token: string) => { /* db() query + signed photo URLs; UI fields only */ })
```

- **The naive version fails the build.** An async page that awaits `params` and `db()` with no boundary fails with `Route "/case/[token]": Next.js encountered uncached or runtime data during prerendering`. Debug it with `next build --debug-prerender`. (02-guides/building.md)
- **Status codes:** `notFound()` inside the boundary runs after streaming has started. The response is therefore **200 + `<meta name="robots" content="noindex">`**, showing our `not-found.tsx` UI. That is acceptable for the MVP. Don't wrap `notFound()` in try/catch. (02-guides/streaming.md; 03-api-reference/03-file-conventions/not-found.md)
- **Only if a real 404 is required:** use `export const instant = false`, an async page that awaits at the top, no `loading.tsx` in the segment, and no `<Suspense>` around `children` in any layout above it. The route then shows ƒ. This does not clear `new Date()` errors. (02-guides/building.md "A blocking product page"; 03-api-reference/03-file-conventions/02-route-segment-config/instant.md)
- **Metadata:** keep the static `metadata` export on the case page. A per-case title would put tenant details in tab titles and browser history. A `generateMetadata` that reads params would be allowed here, because it streams with the deferred content, but it adds nothing. (03-api-reference/04-functions/generate-metadata.md "With Cache Components")
- **Photos:** keep the bucket private and create short-lived signed URLs on the server; `getCaseBundle` already does this. A GET Route Handler for photos would be prerendered unless it touches the request or the DB. A broad try/catch in it also catches the prerender bail-out and adds log noise. (01-getting-started/15-route-handlers.md; 02-guides/migrating-to-cache-components.md "Route Handlers")

## Server actions & forms

- **Files:** put actions in `'use server'` files (`src/app/start/actions.ts`, `src/app/case/[token]/actions.ts`) and make every export async. Exported types are fine. You cannot define an action in a `'use client'` file. (01-getting-started/07-mutating-data.md; 03-api-reference/01-directives/use-server.md)
- **Security:** every action is a public POST endpoint, and the token is the only authorization.
  - Check the token's shape (`isCaseToken`), look the case up by token on the server, and update only that row. Never accept a case id or row contents from the client.
  - Validate every field with zod, even when the input has `required`. `Object.fromEntries(formData)` includes `$ACTION_*` keys.
  - Return small `{ ok, message }` objects, never rows.
  (02-guides/server-actions.md "Security"; 02-guides/data-security.md; 02-guides/forms.md)
- **Errors:** return expected errors as values for `useActionState`. Its signature is `(prevState, formData)`, or `(token, prevState, formData)` when bound. Never show a thrown message: in production it reaches the client as a generic message plus a digest. (01-getting-started/10-error-handling.md; 03-api-reference/03-file-conventions/error.md)
- **Pending state:** use the third value from `useActionState`, or call `useFormStatus()` from `react-dom` in a child of the `<form>`. (02-guides/forms.md "Pending states")
- **Redirect:** call `redirect()` after the insert and outside try/catch. It throws `NEXT_REDIRECT`, defaults to a push in Server Actions, and nothing after it runs. Generate the token in the action, never during render. (03-api-reference/04-functions/redirect.md)

```ts
// src/app/start/actions.ts
'use server'
import { redirect } from 'next/navigation'
import { after } from 'next/server'

export type CreateState = { message: string; errors: Record<string, string> }

export async function createCase(prev: CreateState, formData: FormData): Promise<CreateState> {
  const parsed = newCaseSchema.safeParse(readFields(formData))
  if (!parsed.success) return { message: 'Check the highlighted fields.', errors: toFieldErrors(parsed.error) }
  let created: { id: string; token: string }
  try {
    created = await insertCase(parsed.data, formData.getAll('photo') as File[])
  } catch {
    return { message: 'Could not save your case. Please try again.', errors: {} }
  }
  after(() => logEvent(created.id, 'case_created')) // runs after the response, even on redirect
  redirect(`/case/${created.token}`)
}
```

- **Photo upload:** resize photos on the client, build the `FormData` yourself, and send every photo in **one** action call inside a transition. Use a plain `<form>` or call the action from a handler. `next/form` with a string action submits only the file names. (02-guides/server-actions.md "Sequential dispatch"; 03-api-reference/02-components/form.md)

```tsx
'use client'
import { startTransition, useActionState } from 'react'
import { createCase, type CreateState } from './actions'

const initial: CreateState = { message: '', errors: {} }
export function StartForm() {
  const [state, formAction, pending] = useActionState(createCase, initial)
  function submit(fields: FormData, photos: Blob[]) { // photos already resized to ~300KB
    photos.forEach((b, i) => fields.append('photo', b, `photo-${i}.jpg`))
    startTransition(() => formAction(fields))
  }
  // ...steps; show state.message in <p aria-live="polite">; disable buttons while pending
}
```

- **Reset after create:** because of `<Activity>`, pressing Back from the case page shows the old answers and invites a duplicate case. Set a ref on submit and reset the form in a layout-effect cleanup. (02-guides/preserving-ui-state.md "Forms, inputs, and state")

```tsx
const submitted = useRef(false) // set submitted.current = true right before formAction(...)
useLayoutEffect(() => () => {
  if (submitted.current) { submitted.current = false; setStep(0); setDraft(emptyDraft) }
}, [])
```

- **Case-page forms:** keep them as real `<form action>` elements so they work before hydration. (01-getting-started/07-mutating-data.md)
- **After each deploy:** tabs left open can hit `Failed to find Server Action`. Catch it and show "Refresh the page and try again". (02-guides/server-actions.md "Deployment considerations")
- **Phone testing in dev:** for a tunnel, add its host to both `allowedDevOrigins` and `experimental.serverActions.allowedOrigins`. For a phone on the same Wi-Fi hitting the laptop's LAN IP, add that IP to `allowedDevOrigins`. Leave both unset on Vercel. (03-api-reference/05-config/01-next-config-js/serverActions.md; 03-api-reference/05-config/01-next-config-js/allowedDevOrigins.md)

## Refreshing data after mutations

- **Call `refresh()` in every action that changes a case:** "I sent it", log reply, add photo or note, mark fixed, help request. The case read is uncached, so there is no tag or path to revalidate. `refresh()` throws in Route Handlers. `router.refresh()` is the client-side equivalent. (03-api-reference/04-functions/refresh.md; 02-guides/interactive-apps.md; 03-api-reference/04-functions/use-router.md)

```ts
// src/app/case/[token]/actions.ts
'use server'
import { refresh } from 'next/cache'
import { after } from 'next/server'

export async function markFixed(token: string): Promise<void> { // plain form action: returns void
  if (!isCaseToken(token)) return
  const c = await findCaseByToken(token) // the token is the only authorization
  if (!c) return
  await updateCase(c.id, { fixed_on: nyDate() })
  after(() => logEvent(c.id, 'marked_fixed'))
  refresh()
}
// <form action={markFixed.bind(null, token)}><SubmitButton>Mark fixed</SubmitButton></form>

export async function logReply(token: string, prev: ReplyState, formData: FormData): Promise<ReplyState> {
  if (!isCaseToken(token)) return { ok: false, message: 'Case not found.' }
  const c = await findCaseByToken(token)
  if (!c) return { ok: false, message: 'Case not found.' }
  const parsed = await parseReplyWithClaude(String(formData.get('reply') ?? '').slice(0, 5000))
  if (!parsed.ok) return { ok: false, message: "We couldn't read that reply. Try again." }
  await saveReply(c.id, parsed.value)
  refresh()
  return { ok: true, message: 'Reply saved.' }
}
// const [state, action, pending] = useActionState(logReply.bind(null, token), { ok: false, message: '' })
```

- **Tag APIs are only for tagged `'use cache'` data.** `updateTag(tag)` works only in Server Actions and gives read-your-writes. `revalidateTag(tag, 'max')` does not re-render the current page. None of these throw, but any refresh or revalidation must come before `redirect()`. (03-api-reference/04-functions/updateTag.md; 03-api-reference/04-functions/revalidateTag.md; 02-guides/server-actions.md)

## Routing & file conventions & types

```
src/app/layout.tsx  page.tsx (○)  not-found.tsx  globals.css
src/app/start/page.tsx  actions.ts          (form UI: src/components/start/start-form.tsx, 'use client')
src/app/case/[token]/page.tsx (◐)  actions.ts  not-found.tsx  error.tsx
src/app/api/**/route.ts                     (Route Handlers, never next to a page.tsx)
```

- **`not-found.tsx` takes no props.** The root one also handles unmatched URLs. Don't use `global-not-found.js`, which is experimental. (03-api-reference/03-file-conventions/not-found.md)
- **`error.tsx` must be `'use client'`.** It does not catch errors from the `layout.tsx` in its own segment. A `global-error.tsx` must render its own `<html>`/`<body>`, bring its own styles (import `globals.css`), and use `<title>` instead of `metadata`. (03-api-reference/03-file-conventions/error.md)

```tsx
'use client'
export default function CaseError({ error, retry }: { error: unknown; retry: () => void }) {
  const digest = error instanceof Error ? (error as Error & { digest?: string }).digest : undefined
  return (<div><h2>Something went wrong loading your case.</h2>{digest && <p>Ref: {digest}</p>}
    <button onClick={() => retry()}>Try again</button></div>)
}
```

- **Route Handlers** live in `app/**/route.ts`, never in a segment that has a `page.tsx`. Type the context with `RouteContext<'/api/x/[id]'>` and `await ctx.params`. With Cache Components, a GET handler that reads nothing request-specific is prerendered at build. (01-getting-started/15-route-handlers.md; 03-api-reference/03-file-conventions/route.md)
- **Links:** use `<Link>` from `next/link` with the default prefetch. Import `useRouter` and `useSearchParams` from `next/navigation`. Prefetch runs only in production builds. (03-api-reference/02-components/link.md; 02-guides/prefetching.md)
- **No `proxy.ts` for the MVP.** If one is ever needed, put it at `src/proxy.ts`, export `proxy`, add a matcher, and never set `runtime`. (03-api-reference/03-file-conventions/proxy.md)
- **Type check** with `npm run typecheck` (`next typegen && tsc --noEmit`). A bare `tsc` can fail on a fresh clone because the generated route types (`PageProps` and the others) don't exist yet. (03-api-reference/06-cli/next.md)

## Fonts & metadata

- **Work Sans** is already loaded once in `src/app/layout.tsx`. The import name uses underscores in place of spaces (`Work_Sans`). It is a variable font (wght 100–900), so omit `weight`. Pass `subsets` and a CSS `variable`, then map it with `@theme inline`; Tailwind v4 has no `tailwind.config` font setting. (03-api-reference/02-components/font.md "With Tailwind CSS"; 01-getting-started/13-fonts.md)
- **Use the Metadata API only, with no hand-written `<head>` tags.**
  - Give the title template a `default`; it is required.
  - Theme color goes in `viewport`, not `metadata`.
  - Merging is shallow, so a page's `robots` replaces the parent's.
  - Relative OG URLs need `metadataBase`; without it, the build errors.
  (03-api-reference/04-functions/generate-metadata.md; 03-api-reference/04-functions/generate-viewport.md)

```tsx
// src/app/layout.tsx (matches the repo)
import type { Metadata, Viewport } from 'next'
import { Work_Sans } from 'next/font/google'
import './globals.css'

const workSans = Work_Sans({ subsets: ['latin'], display: 'swap', variable: '--font-work-sans' })
export const metadata: Metadata = {
  title: { template: '%s · Abate', default: 'Abate' },
  description: 'Document an unfixed repair and see the rent abatement you may be owed.',
}
export const viewport: Viewport = { themeColor: '#08014e' }

export default function RootLayout({ children }: LayoutProps<'/'>) {
  return (
    <html lang="en" className={`${workSans.variable} h-full antialiased`}>
      <body className="min-h-full font-sans">{children}</body>
    </html>
  )
}
```

```css
/* src/app/globals.css: @theme inline because it references a runtime variable */
@import 'tailwindcss';
@theme inline { --font-sans: var(--font-work-sans), ui-sans-serif, system-ui, sans-serif; }
```

```ts
export default nextConfig
```

- **Turbopack:** its options go under top-level `turbopack`. Don't add a `webpack()` function or a `--turbopack` flag. (03-api-reference/05-config/01-next-config-js/turbopack.md; 02-guides/upgrading/version-16.md)
- **Agent rules:** `next dev` writes a `nextjs-agent-rules` block into the root `AGENTS.md`, which is our team brief. Either commit the block or set `agentRules: false`; on the next `next dev`, that removes the block. (03-api-reference/05-config/01-next-config-js/agentRules.md)
- **Env names:**
  - `SUPABASE_URL`, `SUPABASE_SECRET_KEY` and `ANTHROPIC_API_KEY`: server-only, and **never** with a `NEXT_PUBLIC_` prefix.
  - `E2E_TEST=1`: set by Playwright to mark test cases.
  - The CC tracking address: `case-view.tsx` reads `NEXT_PUBLIC_CC_EMAIL`. Because a Server Component reads it, an unprefixed `CC_EMAIL` would work and be read at runtime. A `NEXT_PUBLIC_*` value is frozen into the build, everywhere, and changing it needs a redeploy.
  - In client bundles, unprefixed variables become empty strings. `NEXT_PUBLIC_*` values are inlined only for literal `process.env.NEXT_PUBLIC_X` references.
  (02-guides/environment-variables.md; 01-getting-started/05-server-and-client-components.md)
- **Env files:** keep `.env*` at the repo root, not in `src/`. `.env.local` is never committed. `.env.example` lists names only, and it does not exist yet, so create it. `.env.local` is not loaded when `NODE_ENV=test`. (02-guides/environment-variables.md)
- **`server-only`:** start `src/lib/db/*`, `src/lib/cases/repo.ts` and the Claude client with `import 'server-only'`, so importing them from a client component becomes a build error. Keep `src/lib/domain/*` pure so client code can use it (for example `nyDate`). (01-getting-started/05-server-and-client-components.md)
- **Images:** show signed Supabase photo URLs with a plain `<img>` (current code) or `next/image` with `unoptimized`. The docs advise skipping optimization for images that need auth, and it keeps private photos out of the optimizer cache. Configure `images.remotePatterns` only for optimized remote images; `domains` is deprecated. (03-api-reference/02-components/image.md)
- **Taint:** `experimental.taint` is optional and switches React to the experimental channel. Rely on returning only the fields the UI needs instead. (03-api-reference/05-config/01-next-config-js/taint.md)

## Deploy (Vercel)

- **Requirements:** Vercel is a verified adapter. Deploys need Node 20.9+ and TypeScript 5.1+. Supported browsers are Safari 16.4+ and Chrome/Edge/Firefox 111+, so check testers' phones. (01-getting-started/17-deploying.md; 02-guides/upgrading/version-16.md)
- **Before pushing to `main`:** set env vars in Vercel before the build; changing a `NEXT_PUBLIC_*` value needs a redeploy. The build no longer lints, so run `npm run lint`, `npm test` and `npm run typecheck` yourself. (02-guides/environment-variables.md; 02-guides/upgrading/version-16.md)
- **Each deploy can break open tabs and empties the cache.** New deployments usually get new Server Action IDs, so open tabs can hit the stale-tab error (see Server actions). No `'use cache'` entry carries over, because the build ID is part of the cache key. `maxDuration` on `/case/[token]/page.tsx` (60) sets the timeout for every action on that page, including the Claude-backed one; Vercel caps it by plan. (02-guides/server-actions.md; 03-api-reference/01-directives/use-cache.md; 03-api-reference/03-file-conventions/02-route-segment-config/maxDuration.md)
